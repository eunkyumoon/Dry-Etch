## 📝 테스트 케이스 작성 가이드

### 테스트 케이스 명명 규칙
- 형식: `TC-F-XXX_[기능명].md`
- 예시: `TC-F-001_Vpp_Data_Collection.md`

### 테스트 케이스 작성 단계

1. **기능 선택**: [function_list.md](./function_list.md)에서 테스트할 기능 선택
2. **템플릿 복사**: [test_case_template.md](./test_case_template.md)를 복사
3. **정보 입력**: 테스트 케이스 기본 정보 입력
4. **테스트 단계 작성**: 상세한 테스트 단계 작성
5. **검토**: 동료 또는 리뷰어의 검토
6. **승인**: 테스트 케이스 승인

### 테스트 케이스 작성 시 주의사항

1. **명확성**: 각 단계가 명확하고 실행 가능해야 함
2. **재현 가능성**: 다른 사람이 동일한 결과를 얻을 수 있어야 함
3. **완전성**: 모든 시나리오를 커버해야 함
4. **검증 가능성**: 예상 결과가 측정 가능해야 함

- [ ] 관련 문서 검토 완료

### 테스트 실행 프로세스

1. **테스트 계획 수립**
   - 테스트 범위 결정
   - 테스트 일정 수립
   - 리소스 할당

2. **테스트 실행**
   - 테스트 케이스 순서대로 실행
   - 각 단계별 결과 기록
   - 스크린샷/로그 저장

3. **결과 분석**
   - 통과/실패 통계
   - 버그 리포트 작성
   - 개선 사항 도출

4. **리포트 작성**
   - 테스트 실행 리포트
   - 버그 리포트
   - 개선 제안서

## 🐛 버그 관리

### 버그 리포트 템플릿

버그 발견 시 다음 정보를 포함하여 리포트를 작성합니다:

- **버그 ID**: BUG-XXX
- **관련 기능**: F-XXX
- **심각도**: [Critical / High / Medium / Low]
- **우선순위**: [P0 / P1 / P2]
- **재현 절차**: [단계별 설명]
- **예상 결과**: [예상 결과]
- **실제 결과**: [실제 결과]
- **스크린샷/로그**: [파일 경로]
- **환경 정보**: [OS, 브라우저, 버전 등]

### 버그 상태

- **신규 (New)**: 새로 발견된 버그
- **할당됨 (Assigned)**: 담당자에게 할당됨
- **수정 중 (In Progress)**: 수정 진행 중
- **수정 완료 (Fixed)**: 수정 완료, 재테스트 대기
- **검증됨 (Verified)**: 재테스트 통과
- **종료됨 (Closed)**: 버그 해결 완료
